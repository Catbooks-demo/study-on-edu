# 스터디온에듀 — 온라인 강의 플랫폼 설계

2026-11-18, 예진 님 요청("누비투어처럼 실제로 돌아가는 사이트, 여러 온라인 강의 사이트 벤치마킹, 내부·관리자 페이지까지")으로 정함. 이름 "스터디온에듀(StudyOn Edu)"는 검색에서 같은 이름의 실제 회사·서비스가 나오지 않아 그대로 쓴다.

## 왜
AXcellent 시연 고객사 세 번째. 캣북스(쇼핑몰, 주문)·누비투어(여행사, 예약)는 한 번 사고 끝나는 거래다. 스터디온에듀는
- **이어지는 관계**(구독·수강 기간·진도·완강·재구독)와
- **서버가 버티는지가 곧 매출인 업종**(수강신청 오픈, 라이브 강의, 시험 직후 해설 강의에 접속이 몰림)
을 보여 준다. AXcellent의 총괄(이상 신호), 인프라(장애 대응), 고객지원(장애 때 몰리는 문의), 재무(진도 비례 환불·강사 정산), 데이터(완강률·이탈), 마케팅(시즌 캠페인과 서버 용량 조율)을 한 고객사에서 모두 시연할 수 있다.

누비투어처럼 **AXcellent와 독립적**인 사이트다. AXcellent용 주소·이벤트·규격을 넣지 않는다. 실제 강의 플랫폼이 자기 필요로 만들었을 것(관리 화면, 강사 화면, 외부 시스템용 API 키, 상태 확인·지표 주소, 로그)만 있다.

## 목표
- 수강생이 강의를 찾고 → 맛보기 → 구매(단건·패키지·구독, 쿠폰) → 수강(플레이어, 진도, 이어보기, 노트, 강의별 질문) → 완강·수료증 → 후기 → 환불까지 처음부터 끝까지 실제로 동작.
- 라이브 강의: 예약·입장·정원, 시작 시각에 몰리는 입장을 대기열로 받기.
- 강사 화면: 내 강의·수강생·매출·완강률·이탈 구간·미답변 질문, 강의 올리기와 심사 요청, 월 정산 내역.
- 직원 관리 화면: 강의 심사, 주문·환불(계산기), 구독, 쿠폰, 강사 정산 확정, 문의·질문, 공지, 대기열·서비스 모드, 직원·API 키, 작업 기록.
- **안 터지는 운영**: 대기열(가상 대기실), 요청 제한, 무거운 기능부터 끄는 단계별 서비스 모드, 지표 주소, 상태 페이지, 시연용 장애 주입, 부하 시험 스크립트.

## 하지 않을 것 (이번)
- 실제 영상 파일 호스팅·인코딩·DRM. 외부 영상을 내려받아 레포에 넣지 않는다. 강의 영상은 **브라우저에서 그려지는 가짜 영상**(슬라이드·자막이 시간에 맞춰 바뀌는 플레이어, 실제 길이만큼 재생)으로 대신하고, 진도·이어보기·배속은 진짜로 동작한다.
- 실제 화상회의 연동. 라이브는 "입장 → 라이브 화면(가짜 방송 + 실시간 채팅)"까지.
- 실제 돈이 오가는 결제(토스 테스트 키만, `live_` 키면 시작 거부), 실제 문자·메일 발송(보낸 편지함 화면으로 대신).
- AXcellent 연결 작업. 가상 이용자 데이터 생성기는 사이트가 생긴 뒤 다음 단계(설계 아티팩트 먼저).

## 하면 안 되는 것
- 실제 플랫폼(인프런·클래스101·패스트캠퍼스·탈잉·메가스터디·EBSi·에듀윌·유데미·콜로소)의 이름·로고·문구·화면을 베끼거나 그 회사처럼 보이게 하기. 구성만 참고한다.
- 실제 사람처럼 보이는 강사(실명·사진·경력). 강사는 모두 가상 인물이고 화면에 "시연용 가상 강사" 표시.
- 사업자등록번호·원격평생교육시설 신고번호 등 법적 번호를 지어내기. 푸터는 "시연용 가상 서비스" 표시와 빈칸 형식만.
- 키·비밀번호를 레포·로그·화면에 남기기. 공개 레포에 실제 내부 주소 넣기.

## 벤치마킹에서 가져온 구성 (출처: 공개 정책·도움말, 2026-11-18 조사)
- 강의 상세: 맛보기 영상, 가격·할인 마감, 소개, 커리큘럼(섹션 > 강 > 재생 시간, 미리보기 표시), 강사 소개, 수강평(별점 분포·정렬), FAQ, 수강 기간, 환불 규정을 그 페이지 아래에.
- 구매 형태: 단건(수강 기간 N일 또는 평생), 패키지(강좌별 부분 환불 불가), 전체 이용 구독(월·연), 쿠폰(환불은 쿠폰 적용 전 가격 기준으로 계산하는 곳이 있음 → 우리는 **실제 낸 금액 기준**으로 정함, 아래).
- 완강 기준: 영상 총 시간의 80% 이상 시청이면 "완강"(공개 사례) → 수료증 발급.
- 강사 질문 답변 기한: 7일(공개 약관 사례) → 미답변 7일 넘으면 강사·직원 화면에 경고.
- 강사 몫: 일반 판매 70%, 강사 본인 추천 링크로 들어온 판매 90%, 구독 몫은 그달 구독 매출 풀 × 그 강사 강의 시청 시간 비중 × 50%. (공개 사례 70%·97%·구독 별도 방식을 단순화)
- 기기 제한: 계정당 등록 기기 2대(동시 재생 1개). 초과하면 기기 관리에서 해제.
- 접속 폭주 사례: 온라인 개학 오전 9시 일제 로그인 장애, 원서접수 마감 직전 다운, 수능 당일 등급컷·해설, 자격증 가답안 직후 → 대기열(순번·예상 대기 시간), 영상은 별도 경로, 결제 마감 연장 정책.

## 정한 것

### 기술 (누비투어와 같게 — 팀이 이미 아는 구조)
- **Next.js(App Router, TypeScript)** 하나로 수강생·강사·직원 화면과 API. **PostgreSQL + Prisma**, **Tailwind CSS**(외부 UI 키트 없음).
- 결제: 토스페이먼츠 결제위젯 테스트 모드, 키 없으면 모의 결제. 구독 자동 결제는 빌링키 대신 **모의 정기 결제**(같은 표·같은 흐름).
- 실행: `docker compose`(app + postgres). 시험: Vitest(규칙·API), Playwright(핵심 흐름). CI: GitHub Actions(타입·린트·시험·빌드·e2e).
- 실시간(라이브 채팅·대기열 순번 갱신): 서버 전송 이벤트(SSE) + 짧은 주기 조회. 별도 메시지 서버 없음.

### 데이터 (핵심 표, DB 이름은 영어 snake_case, 상태 값도 영어 코드)
- `Category`(개발·프로그래밍, 데이터·AI, 자격증, 어학, 디자인, 비즈니스·마케팅, 수능·내신), `Tag`.
- `Instructor`(가상 강사: 활동명, 소개, 정산 계좌는 끝 4자리만, 상태), `InstructorUser`(강사 로그인).
- `Course`: 코드(`SO-DEV-0001`), 제목, 부제, 카테고리, 강사, 난이도, 가격·할인가·할인 마감, 수강 기간(일, `null`=평생), 상태(`draft`·`in_review`·`published`·`rejected`·`hidden`), 소개, 대상, 선수 지식, FAQ.
- `Section`·`Lecture`(제목, 순서, 길이 초, 미리보기 여부, 자료 첨부 여부, 가짜 영상 스크립트 JSON).
- `Bundle`(강의 묶음, 가격), `Plan`(구독 상품: 월·연, 가격, 포함 범위 = 구독 대상 강의).
- `User`(수강생: 이메일·비밀번호 해시·이름·전화·생년(선택)·관심 분야·마케팅 동의), `Session`, `Device`(기기 이름·첫/마지막 사용, 최대 2대).
- `Order`(주문번호 `SO2611180001`, 수강생, 항목들, 정가 합·할인·쿠폰·결제액, 상태 `pending`·`paid`·`cancelled`·`partially_refunded`·`refunded`), `OrderItem`(강의 또는 패키지), `Payment`(결제/환불 행을 쌓기만, 수단 `toss`·`mock`), `Coupon`(정액·정률, 대상, 기간, 1인 1회, 강사 추천 코드 여부).
- `Subscription`(플랜, 상태 `active`·`past_due`·`paused`·`cancelled`·`expired`, 현재 기간 시작·끝, 해지 예약, 결제 실패 횟수), `SubscriptionInvoice`(기간별 청구·결제·실패·재시도).
- `Enrollment`(수강권: 수강생 × 강의, 출처 `order`·`bundle`·`subscription`·`free`, 시작·만료, 상태 `active`·`expired`·`refunded`), `LectureProgress`(수강생 × 강의 강: 본 초, 마지막 위치, 완료 여부, 마지막 시청 시각), `WatchEvent`(재생 하트비트 기록: 30초마다, 기기, 배속 — 진도 계산과 분석용), `Note`(강·시점·내용), `Certificate`(발급번호·발급일·완강률).
- `Question`·`Answer`(강의별 질문, 강사·직원 답변, 7일 기한), `Review`(완강 40% 이상만, 별점·내용, 숨기기), `Inquiry`(1:1 문의), `Notice`·`Faq`, `Message`(보낸 편지함).
- `LiveSession`(강의 또는 단독, 시작·끝, 정원, 상태 `scheduled`·`live`·`ended`·`cancelled`), `LiveSeat`(예약·입장 시각), `LiveChat`.
- `Refund`(요청: 주문/항목/구독 기간, 사유, 계산 근거(경과일·진도·수강분 금액), 환불액, 상태 `requested`·`approved`·`rejected`·`done`, 처리자).
- `Settlement`(강사 × 월: 판매분·추천분·구독 몫·환불 차감·확정 여부), `SettlementLine`.
- `QueueTicket`(대기열 순번: 대상(`site`·`checkout:<campaign>`·`live:<id>`), 발급·입장 허용·만료 시각), `ServiceMode`(현재 단계·바꾼 사람·사유), `FaultSwitch`(시연용 장애 주입 설정), `Staff`(역할 `admin`·`cs`·`content`), `ApiKey`, `AuditLog`, `JobRun`.

### 규칙
- **수강권**: 단건 구매 → 결제 시각부터 수강 기간(기본 365일, 강의별로 바꿈, 평생 가능). 구독 → 구독이 살아 있는 동안 구독 대상 강의 전부. 구독 끝나면 구독으로 얻은 수강권 만료(진도는 남겨 재구독 때 이어짐).
- **진도**: 플레이어가 30초마다 하트비트(강, 위치, 배속, 기기)를 보내고, 서버가 그 강의 "본 구간"을 합쳐(같은 구간 반복은 한 번만, 배속은 실제 영상 시간 기준) `LectureProgress`에 반영. 강 하나는 90% 이상 보면 완료. 강의 진도율 = 완료한 강 길이 합 ÷ 전체 길이. **완강** = 진도율 80% 이상 → 수료증 발급 가능.
- **기기**: 새 기기로 재생하면 등록(최대 2대, 넘으면 재생 거부와 기기 관리 안내). 한 계정에서 동시 재생은 1개(다른 기기에서 재생하면 앞의 것이 멈춤).
- **환불 (단건·패키지)** — 원격교습 반환 특례(학원법 시행령 별표 4 비고, 평생교육법 시행령 별표 3 비고 4: 낸 금액 − 실제 수강분)와 공개 플랫폼 정책을 합친 것:
  - 결제 후 7일 이내이고 진도 5% 미만이며 자료를 내려받지 않았으면 **전액**.
  - 그 밖에는 **낸 금액 − 수강분 금액**. 수강분 금액 = 낸 금액 × 진도율(완료한 강뿐 아니라 본 구간 비율, 자료를 내려받은 강은 본 것으로 봄). 수강 기간이 있는 강의는 `max(진도율, 경과일 ÷ 수강 기간)`을 쓴다(기간제 공정 공제). 0보다 작으면 0.
  - 패키지는 패키지 전체로 계산(강의별 부분 환불 없음). 쿠폰을 썼으면 **실제 낸 금액**을 기준으로 한다.
  - 환불은 요청 뒤 직원 승인, 승인 뒤 5일 안 처리(법정 기한). 직원이 금액을 조정하면 사유 필수.
- **환불 (구독)**: 결제 후 7일 이내 미시청이면 전액. 그 뒤에는 `공제액 = max(경과일 ÷ 기간 일수, 그 기간 시청한 구독 강의 진도 합 ÷ 기준 시간)` × 결제액(공개 사례 방식). 해지는 다음 결제일에 끝나는 "해지 예약"이 기본.
- **구독 자동 결제**: 기간 끝나기 하루 전 모의 정기 결제. 실패하면 `past_due`, 1·3·5일 뒤 재시도, 세 번 실패하면 `expired`. 수강생은 결제 수단 바꾸기·일시정지(최대 30일, 1년 2번).
- **라이브**: 예약 정원(기본 300)까지 자리 예약, 시작 10분 전부터 입장. 시작 직후 입장이 몰리면 대기열로 받는다(아래). 끝나면 다시보기 강으로 강의에 붙일 수 있음.
- **질문 답변 기한**: 7일. 넘으면 강사·직원 화면에 빨간 표시.
- **강사 정산**: 매월 1일 전월분 계산 → 직원 확정 → 10일 지급 예정 표시. 판매분 70%(추천 코드 판매 90%), 구독 몫 = 그달 구독 결제 합 × 50% × 그 강사 강의 구독 시청 시간 비중. 환불은 환불한 달 정산에서 차감.
- **시간**: 저장 UTC, 화면·날짜 계산 한국 시간.

### 안 터지는 운영 (이 고객사의 핵심)
- **대기열(가상 대기실)**: 대상별로 "1초에 들여보낼 수" 한도를 두고, 넘치면 순번표(`QueueTicket`)를 주고 대기 화면(내 순번, 앞사람 수, 예상 대기 시간, 자동 새로고침)으로 보낸다. 입장 허용된 순번표는 짧은 시간(기본 10분) 쿠키로. 대상: 사이트 전체(평소 꺼짐), 특정 결제 캠페인(예: 할인 마감, 수강신청 오픈), 라이브 입장. 직원 화면에서 켜기·한도·현재 대기 수·평균 대기 시간.
- **요청 제한**: 로그인·가입·결제·질문 쓰기에 IP·계정별 제한(429와 다시 시도 시각).
- **단계별 서비스 모드**(직원이 바꾸거나 지표가 넘으면 자동 제안): `normal` → `degraded`(추천·검색 자동완성·후기 쓰기 등 무거운 기능 끄기, 목록 캐시 길게) → `read_only`(결제·가입·쓰기 막고 수강·재생은 유지, 안내 배너) → `maintenance`(점검 페이지, 직원만). 바꿀 때마다 작업 기록과 공지 배너.
- **지표 주소** `/metrics`(Prometheus 텍스트, API 키 범위 `metrics` 필요): 요청 수·지연 시간 분포(경로 묶음별)·오류율, 동시 재생 수, 대기열 길이·입장 속도, 결제 시도·실패, DB 연결 수·느린 쿼리 수, 작업 실행 시간. `/healthz`(앱), `/readyz`(DB), 공개 **상태 페이지** `/status`(구성 요소별 정상/지연/장애, 진행 중인 장애 공지 — 직원이 쓰는 장애 공지 표 `Incident`).
- **시연용 장애 주입**(`FaultSwitch`, 환경변수 `FAULTS_ENABLED=true`일 때만, 관리자만): DB 지연(+N ms), 영상 하트비트 오류율, 로그인 5xx 비율, 결제 승인 실패율, 특정 경로 지연. 켜고 끈 기록은 작업 기록에.
- **부하 시험**: `scripts/load/` 에 Node 스크립트(의존성 최소, autocannon 정도)로 시나리오 세 가지 — 오전 9시 일제 로그인, 할인 마감 직전 결제, 라이브 시작 입장. 결과 요약을 표로 출력.
- 로그: JSON 한 줄(요청 id·경로·상태·시간, 개인정보·키 제외). 주기 작업은 PostgreSQL advisory lock으로 한 번에 하나.

### 화면 (수강생)
- 메인: 검색, 카테고리, 이번 주 인기, 시즌 기획전(예: "정보처리기사 실기 D-30"), 라이브 일정, 구독 소개, 공지.
- 강의 목록(카테고리·난이도·가격·평점·구독 포함 여부 필터, 정렬), 강의 상세(위 벤치마크 구성), 강사 페이지, 패키지·구독 페이지.
- 장바구니·결제(쿠폰), 완료.
- 내 강의실: 수강 중·완강·만료, 이어보기, 진도율, 수료증(웹 페이지로 보기·인쇄용), 노트 모아보기, 내 질문.
- 플레이어: 가짜 영상, 재생·일시정지·탐색·배속(0.5~2), 이어보기, 커리큘럼 사이드바, 노트(시점 저장), 강별 질문, 자료 받기(가짜 PDF).
- 라이브: 일정·예약, 입장(대기열), 라이브 화면(가짜 방송 + 채팅).
- 마이페이지: 주문·결제·환불 신청(예상 환불액과 계산 근거 미리 보기), 구독 관리(해지 예약·일시정지·결제 수단), 기기 관리, 문의, 회원 정보.
- 고객센터: 공지·FAQ·1:1 문의, 이용약관·개인정보·환불 규정.
- 대기 화면, 서비스 모드 배너, 상태 페이지.

### 화면 (강사, `/instructor`)
- 대시보드: 수강생 수, 이번 달 매출·예상 정산, 강의별 완강률, **이탈 구간**(강별 시청 종료 비율), 평점, 미답변 질문(기한 표시).
- 강의 만들기·고치기(섹션·강·길이·가짜 영상 스크립트), 심사 요청. 질문 답변. 정산 내역. 추천 코드.

### 화면 (직원, `/admin`)
- 대시보드: 오늘 매출·주문·환불 요청·신규 구독·해지·결제 실패, 동시 재생·대기열·오류율 작은 그래프, 미답변 질문·문의.
- 강의 심사(대기열·승인·반려 사유), 강의·패키지·구독 플랜·쿠폰 관리.
- 주문·결제·환불(환불 계산기: 경과일 방식·진도 방식 나란히), 구독(상태·결제 실패 재시도).
- 수강생 상세(수강권·진도·기기 해제), 강사 관리·정산 확정, 라이브 관리.
- 운영: 대기열 설정·현황, 서비스 모드, 장애 공지(상태 페이지), 장애 주입(켜져 있을 때만), 지표 요약.
- 문의·질문·후기, 공지·FAQ, 보낸 편지함, 직원·API 키(관리자만), 작업 기록.

### 외부 시스템용 API (`/api/v1`, Bearer API 키)
- 범위 `read`: 강의·강사·주문·결제·환불·구독·수강권·진도 요약·문의 목록/상세(`updated_since` + 커서). 개인정보는 가림(`김*진`, `010-****-1234`), `read_pii`가 있어야 원문.
- 범위 `write`: 문의 답변, 쿠폰 만들기, 서비스 모드 바꾸기, 장애 공지 쓰기.
- 범위 `metrics`: `/metrics`.
- 웹훅(선택 등록): 주문 결제·환불·구독 상태 변경·서비스 모드 변경을 등록된 주소로 서명해서 보냄(실패 재시도). 플랫폼 자기 규격이고 AXcellent 규격에 맞추지 않는다.
- OpenAPI 문서 `/api/v1/openapi.json`.

### 시드
- 카테고리 7개, 가상 강사 약 20명, 강의 약 60개(카테고리마다 실제로 있을 법한 커리큘럼, 강 길이 5~25분), 패키지 5개, 구독 플랜 2개(월·연), 쿠폰 몇 개, 라이브 일정(앞으로 4주), 공지·FAQ, 직원 계정(비밀번호는 시드 실행 때 환경변수로).
- 이미지: 외부 사진 없이 카테고리별 SVG 일러스트·그라데이션 썸네일.

## 방법 비교
- **A. 누비투어 구조를 따른 자기 규격 독립 사이트 + 운영 기능 (고름)**: 팀이 아는 구조라 빠르고, AXcellent가 낯선 사이트(지표·상태 페이지·웹훅까지 가진)에 붙는 경로를 시험할 수 있다.
- B. 오픈소스 LMS(Moodle 등)를 띄우기: 기능은 많지만 한국식 구매·환불·구독·정산이 없고, 장애 주입·대기열을 넣기 어렵다.
- C. 캣북스를 복사해 강의 상품으로 바꾸기: 빠르지만 연결 모양이 캣북스와 같아 새로 시험할 게 없다.

## 만드는 사람에게 맡김
폴더 구조, 컴포넌트, 강의 60개 내용, 화면 디자인(밝고 집중되는 학습 톤, 고유 브랜드 색 — 누비투어·캣북스와 겹치지 않게), 가짜 영상 표현 방식, 대기열 구현 세부(DB 표 + 메모리 캐시), Playwright 흐름 선택.
